Which open LLM can you trust with health data?

Healthcare AI is moving fast — but most benchmarks are closed, expensive, or not reproducible. HealthLLM is an open leaderboard that scores open-source language models on real clinical tasks: medical knowledge, reasoning, claim verification, disease detection, and RAG reliability.

The problem

Why this exists

🏥

Health AI needs transparency

Models are being deployed in clinical tools, triage systems, and patient-facing apps. Without open, reproducible benchmarks it is impossible to know which models are actually safe to use with health data.

🔬

General benchmarks miss the point

A model that scores well on MMLU can still fail at clinical reasoning, misidentify diseases in a passage, or hallucinate drug interactions. We test specifically for healthcare: facts, reasoning, evidence, and structured output.

📂

Open data, open scores

Every eval uses a publicly licensed dataset. Every score comes from a results file checked into this repo. No proprietary data, no closed judging, no black-box numbers — just runs anyone can reproduce and verify.

🤖

RAG changes the picture

Most health deployments use retrieval-augmented generation (RAG) to ground answers in clinical documents. We test JSON reliability and claim verification — the two capabilities that break first in real RAG pipelines.

The process

How it works

The whole pipeline runs locally. No API keys, no cloud costs — just Ollama and Python.

  1. 1

    Describe your model

    Add a small JSON file to data/models/ with the model name, parameter count, licence, and its Ollama tag. That is the only metadata we store.

  2. 2

    Run the eval script

    The script downloads the benchmark datasets from Hugging Face, asks the model 100 questions per eval at temperature 0, and writes a JSON results file. It takes 20–60 minutes depending on your hardware.

    python evals/run_eval.py --model my-model-7b \
  --hardware "M2 Pro, 16 GB" --submitted-by your-handle
  3. 3

    Open a pull request

    Commit the model file and results file. The health rating — the unweighted mean of all seven evals — appears on the leaderboard automatically once the PR is merged.

Leaderboard

What gets measured

Each eval asks a fixed number of questions sampled with a fixed seed, at temperature 0. Open an eval to see an example of what the model is asked and what counts as right.

Examples are written for this page to show the format. They are not rows from the datasets. Dataset licences are as listed on each dataset card; check the card before reusing the data.

Add a model

Any open model that runs in Ollama can be listed. You need Python 3.10 or newer, Ollama, and a GitHub account.

  1. Describe the model

    Fork the repo and add one file in data/models/. The file name is the model's id.

    // data/models/my-model-7b.json
{
  "id": "my-model-7b",
  "name": "My Model 7B",
  "developer": "Who released it",
  "params_b": 7,
  "license": "Apache-2.0",
  "license_type": "open-source",
  "ollama": "my-model:7b",
  "hf": "org/my-model-7b",
  "medical_tuned": false
}

  2. Run the evals

    Pull the model, then run the eval script. It downloads the datasets, asks the questions, and writes a results file.

    pip install -r evals/requirements.txt
ollama pull my-model:7b
python evals/run_eval.py --model my-model-7b \
  --hardware "M2 Pro, 16 GB" --submitted-by your-handle

  3. Check it

    Validate the data and look at the site locally before you send it.

    npm run check
npm start

  4. Open a pull request

    Commit the model file and data/results/my-model-7b.json. Keep the default sample count and seed so your scores are comparable with the others.

The full guide, including how to list a model without scores and how to propose a new eval, is in docs/ADDING_A_MODEL.md.

Not medical advice, and not clinical validation. A high score on these evals does not make a model safe to use in patient care. Scores come from small samples and are submitted by contributors.
