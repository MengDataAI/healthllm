The problem

Why this exists

🏥

Health AI needs transparency

Models are being deployed in clinical tools, triage systems, and patient-facing apps. Without open, reproducible benchmarks it is impossible to know which models are actually safe to use with health data.

🔬

General benchmarks miss the point

A model that scores well on MMLU can still fail at clinical reasoning, misidentify diseases in a passage, or hallucinate drug interactions. We test specifically for healthcare: facts, reasoning, evidence, and structured output.

📂

Open data, open scores

Every eval uses a publicly licensed dataset. Every score comes from a results file checked into this repo. No proprietary data, no closed judging — just runs anyone can reproduce and verify.

🤖

RAG changes the picture

Most health deployments use retrieval-augmented generation (RAG) to ground answers in clinical documents. We test JSON reliability and claim verification — the two capabilities that break first in real RAG pipelines.

What we measure

7 health evals

Each eval asks 100 questions sampled with a fixed seed, at temperature 0. Every number is fully reproducible.

Examples are written for this page to show the format. Dataset licences are listed on each dataset card; check the card before reusing the data.

Get involved

Add your model in < 1 hour

Fork on GitHub

Any open model that runs in Ollama can be evaluated and listed. No API keys, no cloud costs.

🐍Python 3.10+
🦙Ollama running
🟩Node 18+
🐙GitHub account
💾8+ GB RAM (7B model)
1

Describe the model ~2 min

Fork the repo and create data/models/my-model-7b.json. The id must match the filename.

{
  "id": "my-model-7b",
  "name": "My Model 7B",
  "developer": "Organisation name",
  "params_b": 7,
  "license": "Apache-2.0",
  "license_type": "open-source",
  "ollama": "my-model:7b",
  "hf": "org/my-model-7b",
  "medical_tuned": false
}

💡 license_type is "open-source" for Apache/MIT or "open-weights" for Llama/Gemma licences.

2

Run all 7 evals ~20–60 min

The script downloads the benchmark datasets from HuggingFace, asks 100 questions per eval at temperature 0, and writes your results file.

pip install -r evals/requirements.txt
ollama pull my-model:7b

python evals/run_eval.py \
  --model my-model-7b \
  --hardware "M2 Pro, 16 GB" \
  --submitted-by your-github-handle

Expected output:

Running 7 eval(s) on my-model:7b, 100 samples each
  med-knowledge
  clinical-reasoning
  ...
  Wrote data/results/my-model-7b.json
  med-knowledge          72.3  (n=100)
  clinical-reasoning     65.1  (n=100)

⚡ Useful flags:

--dry-runTest setup without Ollama (fake model)
--samples 20Quick trial run (don't submit)
--evals med-knowledgeRun specific evals only
--inspect med-knowledgeDebug a dataset's field layout
3

Verify locally ~1 min

Check all data files are valid and preview the site before submitting.

npm run check   # validates JSON files
npm start       # preview at http://localhost:4173
4

Open a pull request ~2 min

Commit exactly these two files and open a PR. The CI check runs automatically and a maintainer reviews within a few days.

📄data/models/my-model-7b.json
📊data/results/my-model-7b.json

⚠️ Keep --samples 100 and --seed 42 (defaults) so every model answers the same questions and scores are comparable.
